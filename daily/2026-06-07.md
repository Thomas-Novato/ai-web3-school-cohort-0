# 2026-06-07 学习笔记 — AI Security

> **Core Insight:** AI 安全的本质不是让模型更聪明地拒绝攻击，而是在模型周围建多层防线——输入隔离、权限分级、沙箱执行、操作审计、实时告警。

---

## 01｜为什么要学这个

Agent 一旦能读链、调工具、生成交易、管理 session key，就不再只是聊天机器人。攻击者可以通过文档、网页、合约注释、交易 memo、API 返回值或用户输入影响模型。

**三个核心原则：**
1. 安全是架构问题，不是模型问题——不能指望模型自己识别所有攻击
2. 每个边界都是攻击面——用户输入、网页内容、合约返回、外部 API
3. 纵深防御——即使一层被突破，下层还有防线

---

## 02｜第一性原理

Prompt Injection 不只是"让模型说奇怪的话"。在 Agent 场景里，它可能：
- 诱导模型泄露密钥
- 修改交易目标
- 忽略风险检查
- 调用高权限工具

---

## 03｜八大知识节点

### ① Prompt Injection
恶意内容试图改变模型原始任务或安全规则。

**Web3 攻击面：** 合约 README、网页内容、治理提案、token metadata、交易备注、外部 API 返回

**防护：**
- 分层标注上下文可信级别：用户指令 > 系统规则 > 工具结果 > 外部内容
- 外部内容只能作为待分析资料，不能成为新指令
- 高风险工具不直接听模型一句话

### ② Tool Abuse
模型被诱导滥用工具能力。

**特点：** 常常不是一次大动作，而是很多小动作累积

**防护：** tool permission、rate limit、budget、simulation、human check + 独立异常检测

### ③ Malicious Context
看似普通的上下文里包含攻击指令或**错误事实**——假的合约地址、伪造的审计报告、过期的价格数据。

**关键：** 把"内容"与"指令"隔离

### ④ Key Safety
Agent 管理多个 key（API key、private key、session key）。

**最佳实践：** 密钥不写入 prompt、环境变量/安全存储、定期轮换、权限最小化、可撤销

### ⑤ Permission Isolation
Agent 不同能力应有不同权限级别。

**原则：** 最小权限 + 按需授权 + 人工确认敏感操作

### ⑥ Sandbox
Agent 执行环境与核心系统隔离。

**实现：** 容器隔离、工具调用预处理和后处理

### ⑦ Audit Log
每一步操作完整记录——调了什么工具、看了什么数据、生成了什么交易、谁确认了什么。

### ⑧ Alert
异常行为实时通知——高频调用、陌生合约、超预算、Key 泄露。
